# Software documentation and interface copy

## Documentation

Identify the supported product version and client. Choose the form that serves the need:
a tutorial teaches through a bounded exercise, a how-to solves a task, a reference makes
syntax and defaults easy to look up, and an explanation develops a mental model. Use the
existing structure; these distinctions do not require four separate pages.

Verify the client entry point and resulting behavior, including permissions, defaults and
rollout conditions. Distinguish merged code from shipped capability. Put prerequisites
before the steps they affect and steps in execution order. Show how to recognise success.
For likely failures, give the symptom, verified cause when known and recovery action.
Check examples and commands against the supported version; keep placeholders explicit.

## Websites and interfaces

A full website sweep covers public routes, shared components, page titles, descriptions,
accessible labels and empty or error states. Follow fetched docs to their source. Keep
attribution beside claims and inspect changed wording in rendered pages.

Name controls by their actual labels and actions, rather than position, shape or colour
alone. Use meaningful links, structured headings and appropriate alternative text. Keep
essential instructions available as text beside screenshots or interactive previews.

Match detail to the reader's decision: a landing page can say "steps, model calls and
cost", while an API reference may need exact fields. Preserve accurate names and statuses.
Keep estimated costs, incomplete coverage and comparison limits explicit.

## Verification

Check links, anchors, examples, terminology, accessibility, metadata and alternate outputs.
Run relevant repository checks. Automate broken links, invalid schemas and lost component
text; use source review and walkthroughs for semantics. Mechanical style lint is a
suggestion unless the repository requires it. Report specific unresolved claims and the
verification performed without putting the research log in the product copy.
