## Rules for the whole wave

- **One PR per work item unless the brief says a second PR follows a first.** Each PR green on its own `ci.yml`
  before you send READY. Never merge: send `READY <PR URL> <head sha>` and the coordinator merges.
- **Files you own are listed in your brief.** Eight agents run at once. Do not edit a file another brief owns,
  and do not "tidy" a neighbour's file to make your change fit. If a shared file genuinely must change for your
  item, do the smallest possible edit and say so in the PR body.
- **No version bumps and no tags.** Put your CHANGELOG entry under the next version heading the repo's
  `tools/changelog.py` expects, say which version you proposed, and let the coordinator tag and release.
- **Never fabricate data.** Coordinates, item IDs, NPC IDs, spawn points, prices and level ranges come from the
  client, QuestieDB, or a pinned wago.tools export regenerated by a tool that ships with the repo. If the data
  is not available, ship the honest fallback and say what is missing in the PR body; do not hard-code a guess.
- **Locales.** Every new player-visible phrase goes in all nine translations (`deDE esES esMX frFR koKR ptBR
  ruRU zhCN zhTW`) with machine lines marked `-- mt`, and the repo's `tools/check_locales.py` must pass where it
  exists. Exception: bestiary-forever ships `Locales/enUS.lua` only - keep that as it is.
- **UI changes ship with mocks.** New or changed panels need a mocked scene, a README screenshot, a
  `tools/check_screenshots.py --record` pass, `tools/visual_audit.py` where the repo has it, and your own eyes on
  the rendered PNG at full resolution (overlap, clipping, truncation). A green audit does not prove the picture
  looks right.
- **Gates.** Run every command in the repo's `AGENTS.md` locally and paste the result lines into your report.
- **Do not start a second work item's branch off your own**; cut each branch from fresh `origin/main`.
