## Why, and what it is not

The suite can route you to a dungeon door (Legacy's challenge pins, Tweaks' entrance pins), tell you whether the
run is done (Legacy), what a profession needs (SkillUp), what lives in it (Field Guide's instance grouping) and
whether you are ready (Adventure Guide's AtlasLoot lookups). Nothing answers "show me the instance itself": which
wings, what is inside, where the door is, how long the walk takes. That is a map, and no addon owns a map of an
instance. Atlas Forever owns the **instance map viewer and index** - nothing else.

Boundaries that constrain the build:

- It never judges completion (Legacy) and never draws entrance pins on the world map (Tweaks).
- It never selects quests or decides readiness (Adventure Guide).
- It never catalogues creatures (Bestiary).
- It must work with no other Forever addon installed; every integration is optional and version-checked.

## Scope for v0.1.0

1. **Data from the client, never hand-written.** `Data/Instances.lua` is generated by a new
   `tools/gen_instances.py` from pinned wago.tools DB2 exports, in the mould of
   `tweaks-forever/tools/gen_*`/`legacy-forever/tools/gen_legacy.py`: instance name, mapID, map type, parent
   continent, level range where the client exposes one, entrance coordinates where the client exposes them, and
   the instance's own map art IDs. `tools/check_generated.py` must verify the committed output against the pinned
   inputs (copy the sibling's pattern exactly, including the pins file).
   - Read `tweaks-forever/Data/DungeonEntrances.lua` and `tweaks-forever/Map/DungeonMaps.lua` **for the technique
     they use to obtain entrance and dungeon-map data from the client**, then generate your own copy. Do not
     import their file and do not copy literal values: each addon must work alone (rule 11).
   - If a value is not obtainable, leave it out of the data and let the UI omit the row. **Do not invent
     coordinates, level ranges or boss lists.**
2. **The browser** (`UI/Window.lua`, `UI/List.lua`, `UI/Map.lua`): a window with a continent/filter column and an
   instance list (name, level range, type), and on selection the instance's own map drawn on a canvas - reuse the
   canvas approach and taint precautions of a sibling (`legacy-forever/UI/MapCanvas.lua`,
   `shortest-path-forever/UI/MapCanvas.lua`), never third-party art. Floor/wing selector when the client exposes
   more than one map for the instance; hidden, not faked, when it does not.
3. **Contents.** If - and only if - QuestieDB's NPC rows let you place creatures inside an instance (spawn zone is
   the instance's area, exactly how `bestiary-forever/Integrations/QuestieDB.lua` decides instance membership),
   show a contents column with NPC name, level and rank; where positions are unknown, list names without pins and
   say so in a footnote line. Never place imaginary markers on the map canvas.
4. **Travel button**: "Travel to entrance" -> `ShortestPathForever.API.Navigate("AtlasForever", map, x, y, name,
   "dungeon")` if that API and stop kind exist, else the client's own waypoint
   (`C_Map.CanSetUserWaypointOnMap` + `C_Map.SetUserWaypoint` + `C_SuperTrack`). Follow
   `legacy-forever/Integrations/Navigate.lua` exactly: version check, each function individually checked, honest
   decline, no combat call.
5. **Optional cross-links** (guarded reads, each with a plain fallback): Field Guide
   `API.Species(zoneName)` for a "creatures here" count when it is installed; Legacy `API` only if it exposes
   something read-only and stable. If an API is absent, the tab is simply not drawn. No writes to other addons.
6. Slash `/atlas`, an addon-compartment click if the TOC has one in a sibling, a settings page with: window scale,
   remember last instance, show contents, travel button on/off (default on).
7. README with mocked screenshots of the window (list, map with floor selector, contents, tooltip) rendered
   through the sibling `tools/wowmock` approach into `docs/screenshots/`, plus your own visual inspection at full
   resolution. Match native client styling - read `../wow-retail-ui-style.md`.

## Tests and gate

- `tests/data_spec.lua`: every generated row's shape (mapID integer, coordinates inside 0..1 or absent, map art
  present), no duplicates, sorted deterministically.
- `tests/model_spec.lua`: filter and sort rules (continent, level range, type), selection persistence.
- `tests/api_spec.lua`: the public API below, ready gating, copies.
- `tests/navigate_spec.lua`: SPF path, waypoint fallback, combat decline, no positional data.
- Full gate locally: `luacheck .`, `stylua --check .`, every spec with `luajit`, `ruff check tools`,
  `python3 tools/check_generated.py`, `python3 tools/changelog.py --check`,
  `python3 tools/check_screenshots.py`, `python3 .sift/gate.py --base main` if you add `.sift` rules.

Public API (`AtlasForever.API`, `version = 1`, `minor = 1`, annotated in `types/API.lua`):

```lua
API.Ready() -> boolean
API.Instances(filter?) -> { id, name, mapID, mapType, continent, minLevel?, maxLevel?, entrances? }[]
API.Instance(mapID) -> entry?
API.Open(mapID) -> boolean      -- opens the window on that instance
```
